# 两周实验安排

交付目标日期：2026-11-05（America/New_York）。这是评估期限，盈利由实验决定。
交付物包含能运行的采集、模型、纸面交易、成本账本、日志交接和下一版决策依据。

## 已完成的历史阶段

首版规则在看 BTC 历史结果前固定。2026-08-23—10-21 现已被本实验使用。
不要将任何这段数据的后续调参结果重新称为首次留出验证。
初始结果失败要保留，不能抹掉再声称“从未试过”。

## 前瞻阶段

| 阶段 | 工作 | 判定 |
|---|---|---|
| 10-22—10-24 | 仅采集新盘口/大单数据，继续历史筛选，核对断线、费率和时间 | 未通过历史准入的策略不做前瞻交易 |
| 10-25—10-27 | 主导者检查新数据，最多提出两个预登记修改，并用尚未参与开发的历史区间验证 | 修改不覆盖 v0.1；仍然保留基准 |
| 10-28—11-01 | 只有通过历史准入的固定新版本才开始前瞻模拟 | 观察净收益、成交数、回撤、概率校准，禁止途中按盈亏微调 |
| 11-02—11-05 | 对选定版本做额外时间验证与成本压力评估 | 报告通过/失败/样本不足，以及下一轮方向 |

以上时间安排依赖 Dot 实际启动时间。延迟启动要在日志中标明，不能补写过去的“前瞻交易”。
2–3 天可以形成早期结果，相关交易集中在几天时仍需按日评估不确定性。
每 48–72 小时交付一次日志给实验主导者；Dot 不自行更新模型。

## 每次循环

1. 记录待解决问题及旧版本表现，例如大单是否改善回踩后的收益。
2. 固定新增变量、参数范围、费用、样本期与评价标准。
3. 用已经获得的数据开发，留出未来日期。
4. 只有历史测试合格的版本才进入前瞻纸面交易；失败版本保留报告，继续历史研究。
5. 汇报所有候选，满足净收益与稳定性条件才升级。失败则保留旧版或持币种现金。

自动“不断提高收益”不是可保证的系统行为。循环目标是更快识别无效假设，并保留经新数据验证的改进。
任何版本不得通过降低手续费、忽略空仓、删除亏损或改变本金来提高报表收益。
